# V2.0.1 Release Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Publish a tested, recoverable, sanitized, immutable CardVault V2.0.1 release.

**Architecture:** Keep the current V2 application unchanged except for proven test-fixture or release-tool defects. Reuse the existing account/community APIs, web pages, standalone Docker scripts, Proxmox scratch workflow, backup validation, and GitHub release process. Gather concise evidence in the existing readiness document.

**Tech Stack:** FastAPI, SQLAlchemy, PostgreSQL, React, TypeScript, Vitest, Docker Compose, Bash, Proxmox, GitHub.

**Spec:** `docs/superpowers/specs/2026-09-03-v2.0.1-release-closure-design.md`

## Global Constraints

- Keep the production installation usable throughout.
- Use a disposable member for lifecycle tests; never alter or delete the owner.
- Run focused tests during repair and one complete final gate.
- Never restore over production.
- Never move `v2.0.0`; create `v2.0.1` only after all gates pass.
- Keep all private identifiers and secrets out of public files and test output.
- Stop safely between tasks if usage allowance is exhausted.
