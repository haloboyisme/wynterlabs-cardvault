# V2.7.7 release notes

September 16, 2026. This release includes the background/UI work previously planned for V2.7.6, scanner/recap follow-ups and catalog-refresh recovery.

## Use the new controls

- Account: Personal background, preset + upload, intensity, placement and fit. Choices are saved per account in this browser. Use site background removes that override.
- Admin: Site & branding includes shared background controls. Save applies them to app pages; Restore defaults resets shared design/backgrounds, not cards or accounts. OBS overlay backgrounds remain separately configured in Streamer preview.
- PNG/JPEG/GIF uploads: maximum 1 MB and four million pixels, with dimensions no larger than 4096. GIF uploads include a static fallback. Original trainer, mana and anime-inspired preset artwork is included; it is not official licensed franchise art.
- Low-power is on by default. GIFs use their still during scanning, hidden tabs, reduced motion or low-power mode. Set low-power off to see animation elsewhere. Optional interface sounds remain opt-in; choose soft, glass or retro and motion speed.
- Admin Catalog database defaults to all supported games. Per-game attempts show progress/results and prior active counts. Retry failed games avoids reimporting successful games. A partial run keeps successful updates and reports failed game names.
- Scan supports zoom out/in, wider capture framing and quality guidance. OCR retries rotations and an enhanced image only when needed. Recaps have no fixed card-count cap; practical browser memory/storage limits still apply.

API: 146 targeted checks passed across the main run and a corrected catalog-auth fixture rerun. Private frontend: 653 checks passed across suite and focused reruns.
- Automated web and API checks cover upload validation/reset, account isolation, animation pausing, per-game retry, continued imports after failures, scanner recovery and large recap persistence.
- A 108-card synthetic session exported an audio-enabled browser video with zero missing images. Existing recap persistence tests cover 405 cards. This is not a physical camera endurance test.
- OBS 32.2.2 recorded the actual sound engine's found, accepted, rejected and prize cues through a browser source with Control audio via OBS enabled and monitoring off. The recording contained one stereo audio track with four distinct sound bursts. The temporary test scene was removed and recording stopped; streaming was never started.
- The original missed physical cards were unavailable. Difficult Room/split, sideways, foil, promo and double-faced acceptance, prolonged iPhone/tablet sessions, camera switching, rotation and sleep/resume remain pending. The live account OBS source still requires its private URL and an actual scan recording.
- Video export uses at most eight concurrent image loads and 480×680 card buffers; low-power export runs at 15 fps, otherwise 30 fps. Total export memory still grows with card count and video duration.

## Upgrade and recovery

Back up the database and source before replacing containers. No new migration is introduced beyond the existing 0023 brand design migration. Preserve existing secrets/configuration. Rebuild API and web together and check both health checks. Keep previous images for rollback.

The deployment backup was successfully restored into a separate scratch database with 35 public tables. Both API and web containers passed health checks. Database restore verification never overwrites the production database. Full host disaster recovery and real-device tests remain separate acceptance work.
