# Version 2.5.9 — Custom Card Import

Add cards missing from supported catalogs through the new **Custom Card Import**
navigation page. Enter a name and game/category, with optional HTTPS image,
set, collector number, estimated USD value and quantity.

- Account-private cards integrate with collections and same-game decks.
- JSON import/export carries custom definitions between installations.
- Standard collection CSV retains existing same-account printing-ID behavior.
- User-supplied labels distinguish these cards from provider catalog data.
- Provider refreshes preserve custom cards; account deletion cleans them up.

See the [feature guide](CUSTOM-CARD-IMPORT.md) for file limits and image behavior.

## Installation and upgrades

Use the `v2.5.9` tag with the existing standalone installer. Existing installations
should use the [upgrade guide](UPGRADING.md) and take a fresh backup. This release
adds migration `0021_custom_cards`; removing its ownership columns is deliberately
blocked. Restore backups through the documented recovery process when necessary.

## Verification and scope

Automated API and website tests, TypeScript checking and production build passed.
The database migration passed on an isolated PostgreSQL 17.6 restore, followed
by private-site health and signed-in page verification. Existing bundle-size
advisory remains. A fresh clean-install Docker run was not repeated for this
release; the installer version guard and shell syntax were checked.

Streamer presentation tools remain planned for V3.2 and Bluetooth for V3.5.
Private Hardware Lab code is not part of this public release.
